# Barber Ecosystem

منصة متكاملة لإدارة وتشغيل محلات الحلاقة، الحجوزات، الحلاقين، العملاء، الفروع، الاشتراكات والخدمات المرتبطة بها.

> **الحالة الحالية:** تأسيس المستودع وتوثيق نطاق المنتج. النموذج التفاعلي الأولي السابق هو Prototype محلي مستقل، وليس بعد تطبيقاً متصلاً بخادم أو قاعدة بيانات.

## الرؤية
- **Barber Customer:** اكتشاف المحلات والحجز والولاء والعروض.
- **Barber Pro:** ملف الحلاق المهني، المواعيد، الأداء والفرص المهنية.
- **Barber Business:** إدارة المحل والموظفين والخدمات والحجوزات والفروع.
- **Academy Portal:** إدارة الأكاديميات والدورات والتسجيل والحضور والشهادات.
- **Super Admin:** إدارة المنصة والاشتراكات والمراقبة والدعم.

## هيكل المنتج
- Organization ← Shops ← Branches.
- اشتراك مركزي للمؤسسة مع عناصر فوترة مستقلة للمحلات والفروع الإضافية.
- فصل الملكية القانونية عن أدوار الإدارة والصلاحيات التشغيلية.
- عزل بيانات المؤسسات والمحلات والفروع وفق صلاحيات الخادم.

## هيكل المستودع
- `apps/` تطبيقات المستخدمين.
- `supabase/` مخطط قاعدة البيانات والترحيلات وسياسات الأمان (ستضاف في مرحلة backend).
- `docs/` متطلبات المنتج والقرارات التقنية.

## الحالة التقنية
لا توجد حالياً قاعدة بيانات متصلة أو مصادقة أو دفع أو إشعارات فعلية. لا تضع مفاتيح أو أسرار في المستودع. عند تنفيذ Supabase يجب تفعيل RLS لكل الجداول المكشوفة، وعدم وضع مفاتيح `service_role` في تطبيقات العميل.

## مراحل العمل
1. تثبيت نطاق المنتج والمتطلبات.
2. بناء نموذج البيانات والصلاحيات واختبارها.
3. تطوير Backend والمصادقة.
4. تطوير تطبيقات الموبايل ولوحات الويب.
5. الاختبارات التجريبية ثم الإطلاق.

راجع `docs/product-scope.md` و`docs/architecture.md`.
